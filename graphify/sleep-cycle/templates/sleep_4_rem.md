# Sleep Phase 4: REM (Creative Recombination)

You are the REM phase of the graphify sleep cycle. Runs at 03:30 UTC with `context_from=sleep_3_prune`. Your job: orchestrate three parallel subagents that introduce novelty into the consolidated graph — entity fusion (KGGen-style synonym merging), novel triplet inference (Graphusion-style cross-community edges), and hypothesis nodes (surfacing surprising connections for user review).

## Step 0 — Check upstream

You receive `context_from` from Phase 3 (SHY). Parse the marker:

- `[ok] prune: ...` — proceed
- `[ok] replay: paused for tonight ...` OR `[skipped — upstream paused] prune` — emit `[skipped — upstream paused] rem` and exit
- `[failed: ...] nrem` OR `[failed: ...] prune` — **REM REQUIRES NREM** (Phase 4 operates on consolidated structure from Phase 2). If NREM failed, skip REM with `[skipped — upstream failed] rem`. SHY-only failure is borderline; default behavior is to also skip (creative recombination on stale data produces noise).

Per `safety_gates.md` dependency rules.

## Step 1 — Verify graph + check git counter

```bash
test -f <brain_root>/graphify-out/graph.json || {
    echo "[failed: graph.json missing] rem"
    exit 0
}

# Read commits-this-night counter for failure recovery math
COUNTER_FILE="${HERMES_CRON_OUTPUT_DIR:-$HOME/.hermes/cron/output}/sleep_3_prune/commits_this_night.txt"
PRIOR_COMMITS=$(cat "$COUNTER_FILE" 2>/dev/null || echo 0)
echo "[graphify sleep_4_rem] prior commits this night: $PRIOR_COMMITS"
```

## Step 2 — Dispatch 3 subagents in parallel via delegate_task

Each subagent gets a restricted toolset (no `cronjob`, no nested `delegate_task`, no `memory`, no `send_message`). They write graph mutations via `execute_code`-wrapped graphify subcommands.

### Subagent 1 — Entity fusion (KGGen)

```
delegate_task(
    name="rem_fuse",
    role="leaf",
    goal="Merge synonym entities in the graphify knowledge graph",
    toolsets=["execute_code"],
    prompt="""
    You are the entity-fusion subagent. Run:

        cd <brain_root> && graphify fuse --batch-size 30 --max-fusions 50

    Capture stdout and stderr. The subcommand handles split-mode refusal, EXTRACTED preservation, hyperedge fixed-point chain rewriting, and the per-subagent 50-entity safety gate internally.

    On exit code 0: report '[ok] fuse: <stdout>'.
    On exit code 2: report '[failed: safety gate >50 fusions] fuse' and DO NOT raise — Hermes parent will roll back.
    On other non-zero: report '[failed: <stderr first line>] fuse'.

    Do NOT call graphify push, graphify pull, or any other subcommand. Stay within graphify fuse only.
    """,
)
```

### Subagent 2 — Novel triplet inference (Graphusion)

```
delegate_task(
    name="rem_dream",
    role="leaf",
    goal="Propose novel edges between disconnected communities",
    toolsets=["execute_code"],
    prompt="""
    You are the novel-triplet subagent. Run:

        cd <brain_root> && graphify dream --threshold 0.7 --max-triplets 20

    The subcommand identifies the top 5 largest communities with zero direct edges between them, samples 3 representatives from each, asks an LLM for causal/functional/analogical relations, filters by confidence threshold, applies surviving edges with origin=rem_dream weight=0.5, and applies the per-subagent 50-edge safety gate.

    On exit code 0: report '[ok] dream: <stdout>'.
    On exit code 2: report '[failed: safety gate >50 dreams] dream'.
    On other non-zero: report '[failed: <stderr first line>] dream'.

    Do NOT manually add edges or call other subcommands.
    """,
)
```

### Subagent 3 — Hypothesis nodes

```
delegate_task(
    name="rem_hypothesize",
    role="leaf",
    goal="Surface surprising connections as Hypothesis nodes for user review",
    toolsets=["execute_code"],
    prompt="""
    You are the hypothesis subagent. Run:

        cd <brain_root> && graphify hypothesize --max-hypotheses 5

    The subcommand reads <brain_root>/graphify-out/GRAPH_REPORT.md (regenerated by Phase 2 NREM), extracts the Surprising Connections section, creates 'H: <a> ↔ <b>' nodes with grounded_in edges back to the source nodes, and writes a markdown justification log to <brain_root>/raw/dreams/<date>.md.

    On exit code 0: report '[ok] hypothesize: <stdout>'.
    On exit code 2: report '[failed: safety gate >50 hypotheses] hypothesize'.
    On other non-zero: report '[failed: <stderr first line>] hypothesize'.

    Do NOT call other subcommands or modify graph.json directly.
    """,
)
```

## Step 3 — Collect subagent results

All three subagents commit independently via the working-tree-safe plumbing pattern (mirror of decay's commit logic). Each commit increments the `~/.hermes/cron/output/sleep_4_rem/commits_this_night.txt` counter (atomic update).

If ANY subagent returns `[failed: ...]`:
1. Sum the rollback distance: `n = PRIOR_COMMITS + <commits-this-rem-so-far>`
2. Roll back: `cd <brain_root> && git reset HEAD~<n>` (only this phase's commits revert; Phase 3 SHY and Phase 2 NREM commits stay because `n` counts only sleep_4_rem commits if PRIOR_COMMITS was zero, or stays at `n=PRIOR_COMMITS` if all of REM's subagents failed mid-flight before any commit succeeded).

Per `safety_gates.md`: NEVER `git reset --hard`. Always `git reset HEAD~<n>` where n is precisely the number of commits this phase introduced (not full revert).

## Step 4 — Report

Single status line for `context_from` chain to Phase 5 (Wake, Sprint 4):

- All three subagents OK: `[ok] rem: fuse=<F>, dream=<D>, hypothesize=<H> (total novel entities: <F+D+H>)`
- One or more failed: `[failed: <first-failed-subagent-summary>] rem` (Phase 5 reads the marker and emits a degraded morning briefing with the failure noted)
- All skipped (upstream failure propagated): `[skipped — upstream <state>] rem`

## Safety gates

See `safety_gates.md`. Relevant here:

- **Per-subagent threshold** (Decision #8): Each of `fuse`, `dream`, `hypothesize` independently exits code 2 if it produces > 50 net-new entities. The threshold is PER SUBAGENT, NOT summed. Hermes interprets exit code 2 as "abort this phase, rollback this phase's commits."
- **Budget**: $5.00/night across the three subagents combined (NREM at $3.00 is still the bulk of the night's cost; REM is per-call cheaper but runs three times).
- **Time**: hard timeout 45 minutes (3 subagents × ~15 min each).
- **Working tree**: each subagent uses git plumbing inside its respective graphify subcommand. The user's working tree is never touched.
- **Concurrency**: subagents run in parallel but each commits to `graphify-out/graph.json` sequentially via the graphify plumbing layer. Race condition risk is low because each subagent reads-modifies-writes the full graph; if races happen, the last-write-wins. Acceptable for nightly batch.

## Why three subagents instead of one big LLM call

Per the design doc Section B.2 reasoning: each subagent has a distinct safety profile (fuse can't merge EXTRACTED; dream filters on confidence threshold; hypothesize never calls LLM for label generation). Running them as separate processes:

1. Isolates failure modes (a runaway dream doesn't block fuse from committing)
2. Lets each subagent enforce its own safety gate independently
3. Reduces LLM context per call (lower hallucination rate)
4. Maps cleanly to the per-subagent budget tracking in `cost.jsonl`

The biological metaphor: REM consists of many short bursts of activity, not one continuous process. The three-subagent dispatch mirrors that pattern.
